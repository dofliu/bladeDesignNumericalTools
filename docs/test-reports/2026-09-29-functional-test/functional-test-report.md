## 2. 缺陷清單

### DEF-01(高)結構截面性質求解失效:根部截面積/慣性矩錯誤,葉尖撓度達數百公尺

- **現象**:預設設計(3 葉、R 1.5 m、玻纖、λd 7)於「單葉片」工作區沿展長圖選「結構:揮舞撓度」,標題顯示「葉尖 231747.7 mm」(葉片長度僅 1500 mm,為其 154 倍);停機極端風速工況為 791 m。根部三站的截面性質錯誤:第 1、2 站截面積為質量模型目標的 3.57 倍(等同實心截面),第 3 站(r = 0.302 m)Ixx = −2.92×10⁻⁶ m⁴(負值)。
- **影響**:影響 G.loads.tipDefl / extreme.tipDefl、G.rows[].{secArea, Ixx, Iyy, defl, stress, safety} 與單葉片工作區的三個結構檢視;預設設計的根部安全係數被高估約 2 倍(第 1 站顯示 28.1,修正後為 13.1),第 3 站應力由錯誤面積得出。失效條件是「所需壁厚接近或超過局部翼型半厚」(填充率高的材料、或根部厚翼型)。預設翼型配置的 675 組參數掃描:至少一站 Ixx ≤ 0 的設計 360 組(53%)、至少一站截面積偏離質量模型 > 5% 的設計 675 組(100%,根部 NACA 4421 造成)、葉尖撓度大於葉片長度的設計 341 組。均質翼型 × 材料矩陣(附錄 A)中,10 / 35 組失效,例如 玻纖 + NACA 4421、鋁 + NACA 4421、碳纖 + NACA 4421、PLA + NACA 0012(Ixx < 0,撓度 12,424 m)。
- **根因**:geo.mjs 的 equivalentThickness() 以二分搜尋(區間 [10⁻⁶c, c])反解壁厚,前提是 sectionProperties().area 隨壁厚單調遞增。實測 r = 0.302 m 站(c = 0.18 m、t/c 21%):壁厚 ≤ 11 mm 時面積遞增,超過翼型半厚後 offsetPolygon 的內壁自交,面積遞減(t = 23 mm 時僅 1.3×10⁻⁴ m²)並在 25 mm 突變為實心(46×10⁻⁴ m²)。二分搜尋落在這個不連續點(t = 23.1 mm),回傳面積 9.25×10⁻⁵ m²、Ixx 為負值。bladeLoads() 再以 Math.max(Ixx, 1e-12) 把負值夾成 10⁻¹²,曲率 M/EI = 2668 1/m,積分使全部外側站撓度暴增。
- **建議修法**:(1) 把二分搜尋區間限制在單調區間 [10⁻⁶c, 0.5 × t_max × c],目標面積超出該區間可達面積時改用實心截面;(2) offsetPolygon 增加自交防護;(3) bladeLoads() 遇 Ixx ≤ 0 不要靜默夾值,改為退回實心/警示;(4) 新增迴歸測試:預設設計每站 Ixx > 0、截面積 = 質量模型 ± 5%、tipDefl < R,並涵蓋木材(fill = 1)、PLA(0.42)與 t/c ≥ 20% 的根部翼型。概念驗證(僅在測試環境套用第 1 點,未修改儲存庫):預設設計 16 站截面積比皆為 1.000、葉尖撓度 35.7 mm(現為 231,748 mm)、第 1 站安全係數 13.1(現為 28.1);均質翼型 × 材料矩陣失效組數由 10/35 降為 0/35。
- **相關案例**:B-12、B-13、G-03、N-05

### DEF-02(高)單葉片工作區中把垂直軸改為 Savonius 會使主迴圈永久中斷(模擬與 3D 畫面凍結)

- **現象**:垂直軸模式停在「單葉片」工作區,於「2 轉子」把轉子結構改為 Savonius:主控台出現 TypeError: Cannot read properties of null (reading 'clientWidth'),之後模擬時間不再前進(2 秒內 0.00 s)、3D 場景與 HUD 凍結,只能重新整理頁面。G-07 三次嘗試中 2 次重現(屬時序競爭:每 0.2 秒一次的 Bench.tick 是否落在 140 ms 的去抖空窗內,所以不是每次都發生);狀態轉換掃描 O-01 中,單葉片工作區內由 H、螺旋、Φ、V 改為 Savonius 的轉換全數重現;其餘轉換(改 Φ 型、回到 H 型、用上方按鈕切換水平軸 ↔ 垂直軸等)不受影響。
- **影響**:使用者在單葉片工作區調整轉子型式時可能整個應用程式無回應,需重新載入而遺失未儲存的設計狀態(方案已存於 localStorage,不受影響)。此路徑不在既有 e2e 覆蓋內。狀態轉換掃描(O-01)共 120 次轉換,異常 5 次,全部屬於單葉片工作區 → Savonius。
- **根因**:ui.js 主迴圈每 0.2 秒呼叫 Bench.tick();bench.js 的 tick() 只要 S.vawt.type === 'sav' 就呼叫 renderSav(),但單葉片頁面的 DOM 要等 140 ms 去抖後的 rebuild → afterDesignChange → Bench.render() → layout() 才會換成 Savonius 版面。這段空窗內 $b('bSav') 為 null,fitCv(null) 讀取 .clientWidth 拋出例外。例外發生在 requestAnimationFrame 回呼內,而排程下一影格的 requestAnimationFrame(loop) 寫在回呼最後,因此一次例外就讓整個迴圈永久停止。
- **建議修法**:(1) fitCv 加 null 防護,tick() 先確認 #bSav 存在(或先呼叫 layout());(2) 把主迴圈的 requestAnimationFrame(loop) 移到回呼開頭,或用 try/catch 包住 Bench.tick() / Flow.tick() / hud(),避免任何單一例外使整個應用程式凍結;(3) 新增 e2e:單葉片工作區切換 Savonius 後 2 秒內 SIM.t 仍前進。
- **相關案例**:G-07、O-01

### DEF-03(中)「報告已過時」提示在一般操作流程中不會出現

- **現象**:產生報告後,到「風洞」工作區修改設計(例如 λd 7 → 6)再回到「報告」,提示文字仍是「已產生…設計若再修改,請重新產生報告」,沒有標示報告已過時。即使在報告工作區內(按「顯示設定」)修改設計,提示也不會立即更新,要離開再返回才會顯示「設計已變更…」。
- **影響**:使用者可能下載或列印與目前設計不一致的舊報告而不自知(報告是對外交付物)。
- **根因**:ui.js 的 afterDesignChange() 只在 S.ws === "report" 時呼叫 Report.stale();而 Report.stale() 只設定旗標、不更新畫面,提示文字要等下一次 Report.render() 才會換。在其他工作區修改設計則完全不會標記。
- **建議修法**:產生報告時記錄當時的 G.gen,於 Report.render()(進入報告工作區必定呼叫)比對目前的 G.gen 判斷是否過時;stale() 同時更新提示文字;新增 e2e:改設計後回到報告要顯示過時提示。
- **相關案例**:I-06、I-06b

### DEF-04(低)「快速調整風洞」面板與「3 風洞」設定分頁產生重複的 id(gustBtn、spinUp)

- **現象**:桌面版停在「3 風洞」設定分頁時,DOM 內同時存在兩個 id="gustBtn" 與兩個 id="spinUp"(renderQuick() 與 paneTunnel() 各產生一組)。
- **影響**:違反 HTML 的 id 唯一性,可能干擾輔助科技、label 關聯與外部腳本;目前程式以容器 querySelector 限定範圍,實際功能不受影響。
- **根因**:ui.js 的 renderQuick() 與 paneTunnel() 使用相同的 id 字串。
- **建議修法**:改用 data- 屬性綁定,或給快速面板不同的 id(例如 quickGust / quickSpin)。
- **相關案例**:M-05

## 4. 觀察與備註

- **B-07** 截面表逐站手動覆寫與清除:以 Tab 鍵離開欄位時(焦點仍在截面表內),截面表刻意不重繪以免打斷輸入,因此「已修改」標示(ov)要到焦點離開表格後的下一次重算才更新;數值本身已生效。
- **C-05** 垂直軸型式切換:Savonius 阻力型:最佳 λ = 0.65 略低於面板說明「約 0.7–0.9」(離散網格步距 0.05);屬說明文字與經驗曲線峰值的輕微不一致,不影響功能。 預設 Savonius(R 1 m、H 2 m、玻纖)質量 89.9 kg,其中兩片端板以實心板計算(未套用材料填充率)約占一半,與其他型式採空心殼的質量假設不一致。
- **E-05** 超速/過功率保護(高風速 20 m/s,未啟用切出):風速 20 m/s 且未啟用切出風速時,超速/過功率保護在 90 秒內反覆動作數十次(轉子被煞停再放開),與 CLAUDE.md 記載的已知行為一致(水平軸 14 m/s 以上發電機壓不住固定槳距轉子);建議使用者啟用「切出風速」,日後由變槳(ROADMAP 4)根本解決。
- **E-09** 額定功率限制(發電機 Pmax):發電機額定(500 W)遠小於氣動功率(平均約 2 kW)時,90 秒內保護動作數百次(平均每數百毫秒一次);平均輸出被限制在 1.3 × 額定以內,但煞車—放開的高頻循環對實機的機械/電氣應力值得評估。
- **F-02** 年發電量:年平均風速與 Weibull k:年平均風速欄位標示範圍 2–12 m/s,但程式只夾下限(輸入 50 被接受為 50 m/s;輸入 0 被改為 5 m/s),上限僅靠 HTML max 屬性提示;屬輸入驗證的輕微不一致。
- **F-03** 方案比較:儲存三個方案並持久化:方案自動命名只含翼型與扭角方式:λd、半徑等不同的方案會同名(僅 A/B/C 前綴不同),需手動改名才能區分。
- **G-04** 安全係數過低時的警示:目前僅在圖上畫容許應力線與標題數值,沒有文字警示或色彩警告;此為 ROADMAP 3 驗收條件尚未完成的項目(非回歸)。
- **K-05** 鍵盤與 ARIA 無障礙:匯出視窗按 Esc 不會關閉(僅支援按鈕與點擊背板);屬無障礙建議項。
- **M-04** dist 與原始碼同步(建置可重現):文件同步:README「專案結構」仍列 aero.js / core.js(現為 aero.mjs / core.mjs);CLAUDE.md 中「直接 require src/core.js」「src/package.json 讓 Node 把 core.js 當 CommonJS 載入」等敘述也已過時(PR #32 後 core 已是 ES module)。
- **N-07** 極曲線模型敏感度觀察:薄圓弧板 vs NACA 4412(觀察項,不判定):半經驗模型下,2% 厚的圓弧板升阻比高於 NACA 4412,且彎度愈大愈高(arc:10 在 Re 2×10⁵ 達 113.4);薄圓弧板實務上受前緣分離與形狀阻力影響,通常不會超越 NACA 4 位數翼型,此為極曲線缺少形狀阻力/分離模型的已知限制,選用圓弧板的設計結果會偏樂觀,建議以 XFOIL 或實驗極曲線驗證(ROADMAP 2)。
